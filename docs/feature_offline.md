オフライン閲覧・編集は主にエディタ PoC (`src/editor/ScoreEditorPoc.tsx`) で実現されるローカルキャッシュ機能に依存している。直近アクセスした PDF と手書きストロークを端末内部に保存し、アプリ再起動時や一時的なネットワーク断でも編集を継続できるようにする構造。

### 対象ユーザー・利用場面
対象: リハーサル中にネットワークが不安定な環境で譜面編集を行うメンバー。
利用シーン: 事前に最新譜面を開いた状態でオフラインになっても手書き注釈を続け、オンライン復帰後に保存する。

### 機能詳細要件
- PDF キャッシュ: `getUrl` で取得した署名付き URL を Expo FileSystem 経由で `cacheDirectory` に保存 (`editor-latest.pdf`)。再読込時はキャッシュを削除して常に最新を取得。
- ストローク保存: 描画ストロークを `AsyncStorage` に JSON として保存。キーは `score-editor:strokes:{repo}`、保存件数は最新 MAX_UNDO (=50) に切り詰め。
- 復元: コンポーネントマウント時に `AsyncStorage.getItem` でストロークを復元し、自動的に描画レイヤーへ反映。
- 自動クリーンアップ: アンマウント時にキャッシュ PDF を `deleteAsync` で削除し、描画リセット操作ではストロークキャッシュを削除。
- オフライン保存フロー: オンライン復帰後に `handleSave` が PDF とストロークをマージし S3 へアップロード、差分 API を実行。オフライン中の保存キューは未実装。

### 制約と今後の拡張
- リポジトリ一覧／S3 との同期は常時オンライン前提。完全オフラインでの初回閲覧は未対応。
- キャッシュ PDF は1つのみ保持し、複数リポジトリやページ毎のバージョン管理は未実装。
- ネットワーク状態検知 (`@react-native-community/netinfo`) は依存導入済みだが未利用。今後はオンライン復帰検知と自動同期を実装予定。
- ディスク容量管理、暗号化、キャッシュ有効期限などのポリシー設計が必要。
