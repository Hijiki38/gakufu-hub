楽譜リポジトリ管理・アップロード機能の実装は `App.tsx` の `UploadSection` に集約されている。Amplify Storage (S3) の `data/{repo}/` プレフィックスを仮想リポジトリとして扱い、Expo DocumentPicker で選んだ PDF をバージョン付きで保存し、既存バージョンが存在する場合は差分生成 API を即時呼び出す。

### 対象ユーザー・利用場面
対象: パートリーダー、スコア管理担当者。
利用シーン: リハ前に最新版 PDF を追加アップロードする、あるいは既存リポジトリへ改訂版を投入して差分を取る。

### 機能詳細要件
- リポジトリ一覧: `list({ path: "data/" })` の結果を `path` 2階層目でグルーピングし、タイル表示する。
- 新規作成: 特殊キー `__new__` タイル選択時にテキスト入力で任意リポジトリ名を受け付ける。
- バージョンアップロード: DocumentPicker で取得した PDF を Blob 化し、`data/{repo}/{timestamp}-{filename}` のキーで `uploadData`。`timestamp` は `Date.now()`、既存ファイル名の衝突を避ける。
- 差分トリガー: リポジトリ内に既存 PDF が1つ以上ある場合だけ `post({ apiName: "diffApiv2", path: "diff" })` を実行し、`{ repo, key }` をボディに渡す。
- リポジトリ削除: タイル長押しで `list` した全オブジェクトを `remove`。削除確認ダイアログを表示。
- UI 状態: アップロード成功後は選択状態と入力をリセットし `refreshRepos()` を再実行。Amplify Auth のサインインセッション内でのみ操作可能。

### 保存データ・バージョン戦略
- 原本 PDF: `data/{repo}/` 直下に時刻付きファイル名で順次保存。S3 のバージョニングではなく命名規則で履歴管理。
- 差分アーティファクト: アップロード後の差分 Lambda が `data/{repo}/diff/` 配下に `_diff.pdf` を生成。
- 命名ポリシーはエディタ保存 (`ScoreEditorPoc`) と揃えるため、編集側では ISO8601 形式タイムスタンプを使用。

### 非機能要件・留意点
- 1リポジトリ内のファイル数が多い場合の `list` コスト → ページング未対応のため今後要検討。
- ユーザー入力リポジトリ名のバリデーション（空文字・記号）未実装。
- ゲスト権限にも書き込みが許可されているため、運用時は Cognito グループや IAM ポリシーで制限を強化する必要がある。
